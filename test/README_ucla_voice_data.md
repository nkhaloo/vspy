# UCLA voice project data downloader

[`download_ucla_voice_data.py`](download_ucla_voice_data.py) fetches matched
audio + Praat `.TextGrid` pairs from the
[UCLA Production and Perception of Linguistic Voice Quality project](https://www.phonetics.ucla.edu/voiceproject/voice.html).

## Requirements

Python 3.8+. **No third-party packages** — standard library only (`urllib`,
`html.parser`, `zipfile`). Nothing to `pip install`.

## Running it

```bash
# See what would be downloaded, with sizes. Fetches no audio.
python test/download_ucla_voice_data.py --dry-run

# Download every matched pair (~1.26 GB of archives across 14 datasets).
python test/download_ucla_voice_data.py

# Just one or two datasets (case-insensitive substring match, repeatable).
python test/download_ucla_voice_data.py --only zapotec --only mandarin_ma
```

By default files land in the existing layout — audio in [test/wav/](wav/),
TextGrids in [test/textgrid/](textgrid/) — so a download with the same filename
as an existing file overwrites it. Use `--flat` to write everything directly
into `test/` instead, or `--dest DIR` to target somewhere else entirely.

### Replacing the corpus outright

`--clean` deletes any pre-existing audio/TextGrid files in the destination that
the run did not itself write, leaving only the downloaded set:

```bash
python test/download_ucla_voice_data.py --clean
```

It prunes **after** downloads succeed, never before, and does nothing at all if
the run wrote no files — so an interrupted or failed download can never leave
you with an empty corpus. It only touches audio/TextGrid extensions at the top
level of the two destination directories. Combining `--clean` with `--only` is
refused unless you add `--force`, since that would delete every dataset except
the filtered one.

Useful flags: `--timeout` (default 60s), `--retries` (default 3), `--work-dir`
and `--keep-archives` (stage the `.zip` files somewhere permanent instead of a
temp dir that is deleted afterwards), `--include-egg`. Run with `--help` for the
full list.

## How the site is actually structured

Checked before writing the crawler rather than assumed:

- Every link is in the **static HTML** — nothing is generated by JavaScript, so
  plain HTML parsing is enough.
- The page **does not link individual `.wav`/`.TextGrid` files**. Each language
  ships as a pair of ZIP archives, e.g. `Gujarati/Gujarati_Audio.zip` and
  `Gujarati/Gujarati_TextGrids.zip`.
- Inside an archive, audio and TextGrids sit under different top-level folders
  and are nested in per-speaker subfolders, so pairing is done on the file
  **stem**, which the project keeps identical across the two archives.
- Extension case is inconsistent between languages (`.TextGrid` for most,
  `.textgrid` for Zapotec). Matching is case-insensitive; the original filename
  is preserved on disk untouched.

## What gets downloaded, and what does not

Archives are grouped per directory by a normalised key (the name with the
`audio` / `textgrid` / `egg` marker tokens stripped). A group is only processed
if it has **both** an audio archive and a TextGrid archive. The TextGrid archive
is fetched **first**, so a missing or broken one means the much larger audio
archive is never touched. After extraction only stems present in *both*
archives are written; audio without a TextGrid is discarded and counted.

Deliberately skipped:

- **`*_EGG.zip`** — electroglottograph archives also contain `.wav` files with
  the same stems as the real recordings, so they would masquerade as audio and
  clobber it. `--include-egg` opts back in.
- **Audio-only releases** — English_LRRH (1.3 GB) and Mandarin_LRRH publish no
  TextGrids, so their audio is never downloaded.
- **`English_Sweeps_UnPr`** — the site's only TextGrid link in that folder is
  misnamed `Mandarin_Sweeps_UnPr_TextGrids.zip` and returns **404**.

## Robustness

Relative and absolute URLs both resolved via `urljoin`; crawl restricted to the
host and the `/voiceproject/` path. Every response's status is checked, all
requests are timed out, and transient failures retry with exponential backoff
while 4xx fails fast. A broken link, an unreadable ZIP, or an unexpected error
in one dataset is reported and the run continues. Downloads stream to a `.part`
file and are `os.replace`d into position, so an interrupted run leaves no
truncated `.wav` behind. `__MACOSX`/`._` archive junk is filtered, duplicate
URLs are fetched once, and a basename appearing twice from different sources is
reported as a collision rather than silently clobbered.

The run ends with a count of downloaded / overwritten / skipped / failed files,
a breakdown of skip reasons, and a list of any failures.
